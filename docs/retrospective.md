## 進め方の型

- **最初に1回：** 好きなゲームの面白さを抜き出す → 構想 → 企画まとめを「正」にする（別チャット）→ 作るチャットにはリンクを渡すだけ → リポジトリ・計画のメモ・Issues・マイルストーンを AI が用意 → フェーズごとに作って人が遊んで確かめる

- **最後にまとめて：** 中身がそろってから、前提を決めて全体を調整し、数字を固定する → 見た目 → 高難易度

## 人と AI の役割

- **人が強かったところ：** 何が面白いか（好きなゲームから抜き出す）、仕組みの骨組みと数、ジャンルのお約束、名前、絵と UI の方向、遊んで分かる操作の不満、調整の前提と止めどき。
- **AI が強かったところ：** 企画から画面・戦闘・保存までを短時間で作る、200体と30施設のドット絵をコードで描く、地域を自動で置いて何百回も戦わせる調整、地図や高難易度の地域を作る道具、計画のメモと企画まとめの書き足し、テストで決めた数字を守る。
- AI は決めた前提にまっすぐ合わせる。前提（誰が・どう遊ぶ人に合わせるか）と、ジャンルのお約束は、人が先に言葉にしておく。AI は「残っていること」を自分から並べる。

## 次のゲームで使う手順

Auto Battler の11の手順に、今回の教訓を足した。

1. 好きなゲームの面白さを抜き出し、別のチャットで企画を固める。企画まとめ（Docs）を「正」にして、作るチャットにはリンクを渡す。
2. 企画に「変えないこと」と「ジャンルのお約束」を書く（例：敵も仲間にできる・作れる）。
3. 中身の全体の形を表で決める。モンスター・施設・地域を、属性×役割×地方の表で（足りない所が先に見える）。
4. 名前（ゲーム・地方・地域）と、見た目の方向（参考画像・色）を早めに決める。
5. フェーズは「中身を足す」「見た目」「最終の調整」を分ける。1フェーズは1〜2日で終わる大きさに。
6. フェーズごとに遊んで、番号と理由で答える。決まったことは計画のメモと企画まとめの両方に。
7. 「忘れないようにメモ」は Issue にし、マイルストーンを付ける。AI はフェーズを閉じる前に残りの Issue を並べる。
8. 大量に作るもの（名簿・絵）は、人が見て直せる表やアーティファクトにする。絵は試し描きを2回してから。
9. 調整の前提（仲間・技の数・研究・ふつうの人か工夫する人か）を決めてから、最後にまとめて合わせ、固定する。固定した数字はテストで守る。
10. 調整のあとに足すもの（相性など）は、「難易度を変えるか」を先に決める。
11. 操作の不満は小さくても、すぐ言う（直すのは早い）。
12. 長い計算は、締め切りと「寝る前にどこまで」を書く。

### 頼むときのひな形（今回の分を足した）

```
■目的：何を作る・直すか
■正の文書：企画まとめのリンク（決まったことはここに書き足す）
■変えないこと：遊びの柱、ジャンルのお約束、固定した数字 など
■前提：試すときの仲間・研究・遊び方（ふつうの人／工夫する人）
■目標：数字と、その測り方（何を相手に、何回測るか）
■任せてよいこと：数値の当てはめ、シミュレーション、テスト、絵
■必ず確認してほしいこと：遊びの柱にかかわる変更、全体に効く値の変更、2通りに読める指示
■残っているメモ：Issue 番号（フェーズの終わりに読み上げる）
■報告に入れてほしいこと：勝ち負け・かかった時間・獲得ペース・使われない施設やモンスター・工夫したときとの差
■締め切り：日本時間 ○月○日 ○時
■説明：やさしい日本語で、結論から
```

## 残っていること

- 遊んだあとのフィードバック（人が遊んでから）
- ストーリー（「追々考える」のまま）
- 調整の前提とのずれ：属性の相性を入れたので、基準の仲間は目標より3〜8レベル低く攻略できる（調整しないと決めた）。工夫した配置では、さらに低い
- スマホ対応・セーブの書き出しはやらない（11/11 の決定）
