# Arc-en-ciel Creator 実装計画

最終更新：2026-11-08

**結論：** 静的HTML（ビルドなし）で作り、GitHub で進み具合を管理し、GitHub Pages で公開する。まず第1地方の「草原」1地域だけを仮で作った（フェーズ1）。次は人が遊んで、地域マップの中身（マップの広さ、資源地の数、施設、ウェーブ）を決める。

- 企画の正：Claude Docs「モンスター配置TD 企画まとめ（引き継ぎ用）」 https://claude.ai/artifact/Cp8d8A2xdwkFNeFZQXCb4e
- 用語は企画まとめの「用語の整理」にそろえる（資材・資源地・建設・戦闘施設・進行施設・獲得ペース・図鑑錬成 など）

## 名前

- 英語：**Arc-en-ciel Creator**（Creater → Creator に直した。arc-en-ciel はフランス語で「虹」）
- カタカナ：**アルカンシエル・クリエイター**
- 9属性を虹にたとえて、属性の色は虹の並びを意識している

## 作り方

| 項目 | 決めたこと |
|---|---|
| 形 | 静的HTML＋JavaScript（ESモジュール）。ビルドなし。`index.html` を開けば動く（ローカルでは `npm run serve`） |
| 描画 | 地域マップは canvas、パネルは HTML |
| セーブ | ブラウザの localStorage（端末ごと） |
| テスト | `npm test`（Node の標準テスト）。戦闘・生産・建設は画面と分けて、テストできるようにする |
| 確認の道具 | `npm run sim`：地域を画面なしで最後まで流して、勝ち負け・時間・獲得ペースを出す |
| 公開 | GitHub Pages（main ブランチの一番上のフォルダ）。push すると数分で反映 |
| 進み具合 | GitHub の Milestones ＝ フェーズ、Issues ＝ やること・未決事項。この計画書の表も更新する |

### フォルダ

```
index.html, style.css      画面
src/data/                  数値（属性・モンスター・施設・敵・地方と地域）※調整はここだけ触ればよい
src/core/                  しくみ（マップ・生産と建設・戦闘・セーブ）※画面なしで動く
src/ui/                    描画
test/                      テスト
tools/                     開発用サーバー・シミュレーション
docs/                      この計画書など
```

## 変えないこと（企画まとめから）

- 生産・建設・戦闘は1枚の地域マップで行う。別画面にしない
- 資材は時間で貯まらない。配置で決まる固定の量。地域マップの外へ持ち出さない
- 資材が足りなくなったら、足りない施設のうち最後に建てたものが止まる
- モンスターも施設も戦闘で失わない。負けたらウェーブ1から、失うものはない
- 拠点の耐久は3から（研究で増える）。ウェーブは一律5
- 獲得ペース ＝ 全ウェーブで得たエレメント ÷ 全ウェーブを通しで倒すのにかかった時間。一時停止中はタイマーが止まる
- 戦闘でのモンスターのドロップはない。入手は錬成だけ
- 9属性：無・風・土・水・雷・炎・氷・光・闇

## 第一地域（草原）の仮版で決めたこと

企画まとめで決まっていない所は、次のように仮で決めた。遊んでみて変えてよい。

| 項目 | 仮の決め方 |
|---|---|
| マップ | 28×16マス。道は1本（左から右へ、曲がり角6つ）。道には置けない。木と池も置けない |
| 資源地 | 無4・風2・土2。1マスずつ |
| 生産の量 | 資源地のとなり8マス：+2、攻撃範囲に入っているだけ：+1、同じ属性なら +1 |
| 手持ち | 仮のモンスター5体（無2・風2・土1）。本来は調合錬成で手に入れる |
| 戦闘施設 | 光線塔（無3）、剣の台座（土2・無1、となりの攻撃力+30%）、追い風の旗（風2、2マス以内の攻撃の速さ+30%） |
| 進行施設 | 連戦の角笛（風2・土2）：前のウェーブが出きったら待たずに次を出す。1つまで |
| 敵 | スライム（無）、かぜウサギ（風・速い）、つちモグラ（土・かたい）、ウェーブ5にキングスライム（拠点を2減らす） |
| ウェーブの間 | 4秒あける（この時間もタイマーに入るので、角笛で縮める意味がある） |
| ねらい | 一番先に進んでいる敵 |
| 負けたとき | その挑戦で得たエレメントは持ち帰る |
| 攻略後 | 一番よい獲得ペースを記録。属性ごとの内訳どおりに、1秒ごとにエレメントが入る（ページを開いている間だけ） |

`npm run sim` の見本の配置では：モンスターだけだとウェーブ5で負け、光線塔・剣・旗を建てると拠点1残りで攻略（約300秒、ペース0.32/秒）、角笛を入れると資材が足りず旗が止まって負け。

## 人に確認してほしいこと（フェーズ2で決める）

1. マップの広さと、マスの小ささ（今は28×16）。もっと広い方がよいか
2. 生産の量の決め方（となり+2／範囲+1／同じ属性+1）
3. 負けたときに、その挑戦で得たエレメントを持ち帰るか（今は持ち帰る。ウェーブ1だけをくり返して稼げてしまう）
4. 攻略後の自動獲得を、ページを閉じている間も進めるか
5. 戦闘中にモンスターを動かしてよいか（今は動かせる。資材が変わると施設が止まる）
6. 施設の案（他にほしいもの）

## 頼むときのひな形（auto-battler のふり返りから）

```
■目的：何を作る・直すか
■変えないこと：遊びの柱、決めたルール など
■目標：数字と、その測り方（何を相手に、何回測るか）
■任せてよいこと：数値の当てはめ、シミュレーション、テスト
■必ず確認してほしいこと：遊びの柱にかかわる変更、全体に効く値の変更
■報告に入れてほしいこと：勝ち負け・かかった時間・獲得ペース・使われない施設やモンスター
■締め切り：日本時間 ○月○日 ○時
■説明：やさしい日本語で、結論から
```
