## 名前

- 英語：**Arc-en-ciel Creator**（Creater → Creator に直した。arc-en-ciel はフランス語で「虹」）
- カタカナ：**アルカンシエル・クリエイター**
- 9属性を虹にたとえて、属性の色は虹の並びを意識している

## 作り方

| 項目 | 決めたこと |
|---|---|
| 形 | 静的HTML＋JavaScript（ESモジュール）。ビルドなし。`index.html` を開けば動く（ローカルでは `npm run serve`） |
| 描画 | 地域マップは canvas、パネルは HTML |
| セーブ | ブラウザの localStorage（端末ごと） |
| テスト | `npm test`（Node の標準テスト）。戦闘・生産・建設は画面と分けて、テストできるようにする |
| 確認の道具 | `npm run sim`：地域を画面なしで最後まで流して、勝ち負け・時間・獲得ペースを出す |
| 公開 | GitHub Pages（main ブランチの一番上のフォルダ）。push すると数分で反映 |
| 進み具合 | GitHub の Milestones ＝ フェーズ、Issues ＝ やること・未決事項。この計画書の表も更新する |

### フォルダ

```
index.html, style.css      画面
src/data/                  数値（属性・モンスター・施設・敵・地方と地域）※調整はここだけ触ればよい
src/core/                  しくみ（マップ・生産と建設・戦闘・セーブ）※画面なしで動く
src/ui/                    描画
test/                      テスト
tools/                     開発用サーバー・シミュレーション
docs/                      この計画書など
```

## 変えないこと（企画まとめから）

- 生産・建設・戦闘は1枚の地域マップで行う。別画面にしない
- 資材は時間で貯まらない。配置で決まる固定の量。地域マップの外へ持ち出さない
- 資材が足りなくなったら、足りない施設のうち最後に建てたものが止まる
- モンスターも施設も戦闘で失わない。負けたらウェーブ1から、失うものはない
- 拠点の耐久は3から（研究で増える）。ウェーブは一律5
- 獲得ペース ＝ 全ウェーブで得たエレメント ÷ 全ウェーブを通しで倒すのにかかった時間。一時停止中はタイマーが止まる
- 戦闘でのモンスターのドロップはない。入手は錬成だけ
- 9属性：無・風・土・水・雷・炎・氷・光・闇
- 攻撃・効果の範囲はマス目の形。向きで範囲の方向が決まる（フェーズ2で決定）
- 最後のボスを通したら拠点は全損。ボスを倒さないとクリアにならない（フェーズ2で決定）
- 負けても、その挑戦で得たエレメントは持ち帰る。勝てないときに新しいエレメントで何をするかもサイクルの一つ（フェーズ2で決定）
- 攻略後の自動獲得はページを開いている間だけ。求めるのは放置ではなく、挑戦と改善のサイクル（フェーズ2で決定）
- 戦闘中にモンスターも施設も動かせる。動かしたら攻撃は溜め直し（フェーズ2で決定）

## 第一地域（草原）の今の中身（v0.2.0）

| 項目 | 今の決め方 |
|---|---|
| マップ | 28×16マス（OK）。道は1本（左から右へ、曲がり角6つ）。道・木・池には置けない |
| 資源地 | 無4・風2・土2。1マスずつ |
| 生産の量 | 資源地のまわり8マス：+2、攻撃範囲のマスに入るだけ：+1、同じ属性なら +1（OK） |
| 範囲 | マス目の形。上を向いたときの絵でデータに書き、向きに合わせて回す（`src/data/` の shape） |
| 向き | モンスターも施設も上・右・下・左。R キーか「回転」ボタンで回す。横長の施設も回る |
| 手持ち | 仮のモンスター5体（無2・風2・土1）。本来は調合錬成で手に入れる |
| 戦闘施設 | 光線塔（無3、前へまっすぐ8マス）、剣の台座（土2・無1、まわり8マスの攻撃力+50%、鍛冶場が動いている間だけ）、追い風の旗（風2、前の6マスの攻撃の速さ+30%） |
| 製造施設 | 鍛冶場（土1、横2マス）。前の2マス（作業場所）にモンスターを置くと動く。作業中のモンスターは攻撃も生産もしない |
| 進行施設 | 連戦の角笛（風2・土2）。重ねて置ける。1個で2ウェーブずつ（2-2-1）、2個で3ウェーブずつ（3-2） |
| 敵 | スライム（無）、かぜウサギ（風・速い）、つちモグラ（土・かたい）、【強】おおモグラ（拠点を2減らす）、【ボス】キングスライム（通したら全損） |
| ウェーブの間 | まとめて出したウェーブを全部倒してから4秒あける（この時間もタイマーに入る） |
| ねらい | 範囲のマスにいる敵のうち、一番先に進んでいる敵 |
| 自動で再挑戦 | オンにすると、勝っても負けても1.5秒後に次の挑戦を始める |

`npm run sim` の見本の配置（ボスの体力260）：

| 配置 | 結果 | かかった時間 | 獲得ペース |
|---|---|---|---|
| モンスターだけ | ウェーブ5でボスを通して負け | 342秒 | 0.31/秒 |
| 光線塔＋旗 | 攻略（拠点3） | 308秒 | 0.38/秒 |
| 鍛冶場＋剣（コウモリが作業、剣でスライムとタカを強化） | 攻略（拠点3） | 339秒 | 0.34/秒 |
| 角笛1個 | ウェーブ3と4をまとめて出され、ウェーブ4で負け | 125秒 | 0.50/秒 |

## 周回のペース（Issue #4 の確認）

自動で再挑戦したときに、1周ごとに入るエレメント ÷ 1周の時間（再挑戦までの1.5秒を含む）。

| 配置 | 1倍速 | 8倍速 |
|---|---|---|
| 光線塔＋旗（攻略） | 0.38/秒 | 2.90/秒 |
| 角笛1個（ウェーブ4で負け） | 0.49/秒 | 3.62/秒 |
| モンスター1体（ウェーブ1で負け） | 0.02/秒 | 0.12/秒 |

- 1倍速なら、周回は攻略後の自動獲得（記録したペース）とほぼ同じ。ウェーブ1だけで負ける周回はとても遅い
- **倍速で周回すると、実際の時間あたりは倍速の分だけ速くなる**（8倍速なら約8倍）。自動獲得より速いサイクルになる
- 角笛で早く負ける周回が、角笛なしで攻略するより速い（0.49 > 0.38）

## 人に確認してほしいこと

1. 倍速での周回をどうするか（例：自動で再挑戦の間は速さの上限を決める、倍速は見た目だけにして獲得は実時間で数える、など）
2. 鍛冶場の作業中のモンスターは、生産もしない（今）でよいか
3. 剣の台座 +50% と鍛冶場（土1）の重さ。見本では、コウモリを作業に回しても攻略できる程度
4. ボスの体力（今は260。範囲がマス目になって当たる道のマスが減ったので、700から下げた）

## 頼むときのひな形（auto-battler のふり返りから）

```
■目的：何を作る・直すか
■変えないこと：遊びの柱、決めたルール など
■目標：数字と、その測り方（何を相手に、何回測るか）
■任せてよいこと：数値の当てはめ、シミュレーション、テスト
■必ず確認してほしいこと：遊びの柱にかかわる変更、全体に効く値の変更
■報告に入れてほしいこと：勝ち負け・かかった時間・獲得ペース・使われない施設やモンスター
■締め切り：日本時間 ○月○日 ○時
■説明：やさしい日本語で、結論から
```
